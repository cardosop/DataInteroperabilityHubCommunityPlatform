# Reverse Lookup Analysis

## Overview

This document summarizes the comprehensive analysis of Django URL reverse lookups in the codebase.

## Analysis Results

### Summary Statistics

- **Total reverse() calls found**: 258
- **Total {% url %} template tags found**: 0
- **Total URL patterns found**: 188
- **Mapped reverse lookups**: 30
- **Unmapped reverse lookups**: 7
- **Reverse lookup dependencies**: 34

### Tools Created

1. **`scripts/analyze_reverse_lookups.py`**: Comprehensive script that:
   - Searches for all `reverse()` calls in Python code using AST parsing
   - Searches for `{% url %}` template tags in HTML/template files
   - Maps reverse lookups to URL patterns in `urls.py` files
   - Identifies reverse lookup dependencies
   - Generates a JSON report with all findings

2. **`hub/apps/core/tests/test_reverse_lookups.py`**: Test suite that:
   - Verifies all reverse lookups can be resolved
   - Verifies reverse lookup mapping to URL patterns
   - Documents unmapped lookups

### Unmapped Reverse Lookups

The following reverse lookups could not be automatically mapped to URL patterns:

1. **`virtual-dataset-`** (2 occurrences)
   - **Reason**: Dynamic reverse call using f-strings (e.g., `reverse(f'virtual-dataset-{action}')`)
   - **Status**: Expected - these are test-only dynamic lookups

2. **`search-search`** (4 occurrences)
   - **Reason**: Custom action on SearchViewSet
   - **Status**: Needs manual verification

3. **`search-suggestions`** (4 occurrences)
   - **Reason**: Custom action on SearchViewSet

4. **`search-track-click`** (2 occurrences)
   - **Reason**: Custom action on SearchViewSet
   - **Status**: Needs manual verification

5. **`contract-create-product`** (20 occurrences)
   - **Reason**: Custom action with `url_name="create-product"` on ContractViewSet

6. **`contract-link-odps`** (24 occurrences)

   - **Status**: Needs manual verification

### Key Findings

1. **DRF Router Patterns**: Most URL patterns are generated by DRF routers (`DefaultRouter`), which create URL names in the format `{basename}-{action}` (e.g., `virtual-dataset-list`, `query-execution-detail`).

2. **Custom Actions**: Custom viewset actions use `@action` decorators and generate URL names as `{basename}-{method_name}` (e.g., `virtual-dataset-validate-dataset`).

3. **Template Tags**: No `{% url %}` template tags were found in the codebase, indicating all URL references are in Python code.

4. **Dependencies**: 34 reverse lookup dependencies were identified, showing how different parts of the codebase reference each other's URLs.

### Usage

#### Running the Analysis

```bash
python3 scripts/analyze_reverse_lookups.py
```

This generates `reverse_lookup_analysis.json` with detailed findings.

#### Running Tests

```bash
# Run reverse lookup tests
pytest hub/apps/core/tests/test_reverse_lookups.py -v
```

### Recommendations

1. **Manual Verification**: The 7 unmapped reverse lookups should be manually verified to ensure they resolve correctly.

2. **Documentation**: Consider documenting custom action URL naming conventions in the project documentation.

3. **CI Integration**: Add the reverse lookup analysis script to CI/CD pipeline to catch broken reverse lookups early.

4. **Regular Updates**: Run the analysis script periodically (e.g., before releases) to ensure reverse lookups remain valid.
