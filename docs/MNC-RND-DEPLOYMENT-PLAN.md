## 2. Executive summary — verdict delta

The verdict stands: this platform is a **strong governance, interoperability, and commercialization layer for a Databricks-on-AWS estate** and should not become a scientific data platform at go-live. The audit sharpened it in seven places where the plan's own claims were false:

1. **"O1 is replication of a proven scaffold" — false.** Production terraform has never been applied ("PROD INFRA — NOT YET DEPLOYED", [../infrastructure/terraform/environments/prod/main.tf:1](../infrastructure/terraform/environments/prod/main.tf#L1)), and the region is a literal string in provider blocks, the shared VPC AZ list, state backends, and CI ([../infrastructure/terraform/modules/vpc/main.tf:28](../infrastructure/terraform/modules/vpc/main.tf#L28)). O1 is a **first-ever production standup + parameterization refactor**, then replication.
2. **"D2/C5 deliver 7 visible IP grades with ~zero code" — false.** There is no manual classification write path anywhere (only the auto-classifier, which never emits RESTRICTED; approve/reject service methods are dead code, [../hub/apps/governance/classification.py:411](../hub/apps/governance/classification.py#L411)); the frontend renders no classification at all. C5 rescopes to a manual assignment endpoint + steward UI + badges (S→low-M).
3. **"D1 + decision 6 need no schema" — incomplete.** Tenant/User ids are instance-local uuids; no cross-instance identity exists ([../hub/apps/tenants/models.py:383](../hub/apps/tenants/models.py#L383)). A legal entity spanning two regions has no recorded home. The entity→host-instance rule must be recorded before O1 seeds tenants.
4. **"D6's orchestration taxonomy is complete" — false.** **Prefect is the scheduler of record for scheduled_ingestion/scheduled_export** (cron = Prefect deployments; no in-app cron tick exists; the server is outside the Helm chart and both worker/integration default disabled). A deployment following D6 literally ships scheduled ingestion that silently never fires.
5. **"Terraform envs bring the Databricks estate online" — false.** Every estate feature keys off a hub-registered workspace whose service credential must carry an APPROVED Phase-272 approval linkage ([../hub/apps/databricks_admin/cost_sync.py:160](../hub/apps/databricks_admin/cost_sync.py#L160)); account link/provisioning is API + signoff + human approval chains — **calendar-bound, start week 1**.
6. **"§2 governs the estate's primary data type" — false.** `ALLOWED_FILE_TYPES` defaults to csv/json/parquet/txt/xlsx/xls ([../hub/settings.py:1530](../hub/settings.py#L1530)) — spectra/HDF5/NetCDF/ADF uploads are **rejected**; no hub-files→UC bridge exists; Delta Sharing serves tables, not raw files. A day-1 instrument-intake path (D8) is mandatory.
7. **"O1 replicates the whole stack" — false.** Observability (Prometheus/Grafana/Alertmanager/Loki/Tempo) lives in a third deployment mechanism (kustomize + compose), region-less, with no alert delivery anywhere (all receivers are placeholders). Per-region monitoring is unplanned work.

**Rescaled headline:** go-live < 3 months is achievable only if Phase 0 is recharacterized from "decisions + ~155–410k tokens of closes" to "decisions + rescaled closes + O1 engineering sub-items (first standup, parameterization, observability, Prefect, capacity) + a bootstrap workstream (existing-estate migration, identity/clearance bootstrap, org-transfer of CI/QA) + calendar-bound estate onboarding started immediately".

**No-surprise check (this section):** an implementer who trusts §5 "carries forward unchanged" without reading the audit will discover mid-build: prod never stood up; instrument uploads rejected; scheduled ingestion silent; observability absent per region; no manual grade assignment; cross-region entities homeless.

The dlt staging external-location seam ([../hub/data_movement/staging.py:129](../hub/data_movement/staging.py#L129)) is the named candidate for a future hub-files→UC bridge.
- **Estate:** hub-side tenant isolation does not extend into UC unless the metastore is per-tenant (D-meta).
- **DR:** per-region DR is in-region only (multi-AZ, RDS snapshot/PITR, S3 versioning/Object Lock); [../docs/operations/multi-region-dr-plan.md](../docs/operations/multi-region-dr-plan.md) is **superseded** for this estate (D-sr).

## 6. Phase 0 (go-live < 3 months) — revised, with bootstrap workstream

**The bootstrap workstream (highest-value addition from the completeness critic)** — the plan treated the deployment as a clean tree into a greenfield org; it is not:

- **B1. Existing-estate migration:** SCIM to Databricks is live — existing workspaces, tables, jobs, users exist. Whose AWS accounts, GitHub org, ECR registries, and domains does the MNC use? Unrecorded.

Calendar critical path + staffing:** SOC 2 Type II needs ≥3 months of live operation (report lands after go-live; the observation window's control-freeze collides with the phase-1 build wave); ISO 27001 stage-1→2 spans months; DPO signoffs, provisioning signoffs, Phase-272 approval chains, IdP-team changes, SES/DNS verification, audit-firm selection — all serial, all inside 3 months. ## 24. Root-cause remediation strategy (RC1–RC5)

**Meta-diagnosis:** seven blockers, one underlying disease — **the platform has never been exercised in a real deployment, so "shipped" ≠ "deployed"**. Prod never applied, alert receivers are placeholders, SLO rules select labels that don't exist, the DR doc describes an architecture that was never built, the region is a literal string, and the scheduler of record lives outside the deploy artifact. The fix is not seven point-patches but **five root-cause remedies that make deployment-truth a machine-enforced property of the codebase**, each reusing a mechanism the repo already trusts (pinned-pair settings tests, GATE-54 AST checker, strict load gate, stuck-run detectors, chain doctrine).

**RC1 — Deployment-truth gate: nothing carries forward unless production-exercised.** Fixes blockers 3, 7 + the critic's audit-window/org-transfer items. Generalize the k6 strict-gate philosophy (it already refuses to bless unconfirmed scale, [../scripts/run_week1_load_test.py:174](../scripts/run_week1_load_test.py#L174)) into a go-live acceptance machine: per-capability **exercised evidence** (prod apply + smoke, a real alert delivered to a human, restore drill against the actual RDS snapshot/PITR path, estate syncs firing, day-1 E2E journey passing) — no evidence, no go-live. Ship as `scripts/check_go_live_evidence.py` (advisory in CI until go-live, blocking on go-live day). The first-ever prod apply becomes the calibration run; every region inherits an exercised posture. The org-transfer of meshant-branded CI/QA becomes a named evidence item per region (whose AWS account, GitHub org, ECR registry, domain).

**RC2 — Deployment-profile abstraction: configuration as data, not literals.** Fixes blockers 1, 3, 6 (partially) + the Tier-2 config siblings (rate limits, BLOCK-default budgets, PgBouncer/HPA contradiction, PDB). One profile layer (`DEPLOYMENT_PROFILE` env selecting a profile module): regions list + per-region hosts, scale tier driving defaults (throttles sized for 500–2,000 users, budget enforcement default ALERT, pool/HPA reconciliation, file-type allowlist per deployment policy, kill-switch defaults, CI/QA endpoints). Two guards in the repo's own style: (a) a **no-hardcoded-region AST lint** (pattern: GATE-54 `check_provider_boundary.py`), (b) a **config-drift pin test** asserting profile values vs shipped defaults (pattern: `test_rls_guc_settings_sync.py`). Blocker 1 fix lands now, not as a deferred decision: add `Tenant.external_org_id` (IdP org GUID, indexed, unique per instance, backfilled — ~1 migration, a deliberate small reversal of the earlier "no schema change" call) + the entity→host-instance rule recorded in the profile. Identity that exists only as a uuid4 inside one database is not identity.

**RC3 — Single deployable surface + component inventory.** Fixes blockers 5, 7. One rule: every runtime dependency is **either in the Helm chart + CI deploy path, or registered in an external-dependency inventory** (component, deploy mechanism, health check, absence-alert rule). Fold Prefect (external chart + worker + integration + Postgres) and the observability stack into the chart with per-region values — they become part of what O1 replicates by construction, not by memory. Add a **boot-time component-liveness check per region**, extending the existing stuck-run detection cronjobs with expected-but-absent detectors (Prefect API unreachable while scheduled jobs are configured → alert; a region's Prometheus not scraping → alert). Blockers 5 and 7 share the failure class *silently absent components*; this converts that class from silent to observable — the actual root-cause fix.

**RC4 — Explicit write-paths and fail-closed chokepoints for security-relevant state.** Fixes blockers 2, 4 + pre-empts E1/CL1 + resolves the critic's user-side clearance gap. The repo's own business-rules-chain doctrine applied to state mutation: if a state value matters for security, it must be (1) **writable only through a validated path** — permission policy + audit event — and (2) **read only through a fail-closed path**. Concretely: classification — wire the dead `approve_classification`/`reject_classification` methods ([../hub/apps/governance/classification.py:411](../hub/apps/governance/classification.py#L411)) into a real endpoint + steward UI, add a CheckConstraint on `category`, make the ABAC priority lookup data-driven and fail closed on unknown instead of defaulting to INTERNAL ([../hub/apps/governance/abac.py:305](../hub/apps/governance/abac.py#L305)); estate provisioning — ship an **estate-onboarding management command** that registers the workspace and raises the approval-linked credential request through the existing Phase-272 chain machinery (approvals stay human; the work becomes scriptable, one-click-per-step, auditable, repeatable across N regions); gates the plan will copy — fix the compliance-gate silent-pass branches **before** E1 mirrors them (NULL `allowed_to_store` blocks, per the CLAUDE.md "not True" contract), and guard `plan_uc_grants` against export-conditioned policies; clearance — a `Clearance`/attribute store synced from HR via the I1 sync job, ABAC consuming only the stored value (the E1/I1 shape, nothing new architecturally).

**RC5 — Planning discipline (the meta-fix).** Fixes the critic's structural blind spots. Four rules: (1) **calibrate before committing** — run C1–C5 first and measure the real overhead multiplier against the assumed 2–3×; (2) **verify before locking** — the 55 Tier-2 findings get their adversarial pass before any phase-1 estimate is treated as real; (3) every decision carries owner + sign-off + DoD (enforce §5); (4) **the calendar is staffed, not assumed** — approval chains, DPO signoffs, IdP-team changes, SES/DNS verification, and the SOC 2 observation window get week-1 start dates and named humans. AI-assisted delivery is a multiplier on execution, not a substitute for the staffing model.

| --- | --- | --- | --- |

**Execution order:** Week 1 — RC2 identity migration + profile skeleton, RC3 inventory registration, RC4 compliance-gate fix, start every calendar gate.
