# Semantic bulk RDF export — runbook

**Phase:** 230.2 (REQ-SEM-EXPORT-001)
**Owner:** Data Platform Eng
**Last reviewed:** 2026-05-01

This runbook covers operational procedures for the bulk RDF
export endpoint at `POST /api/v1/semantic/export` and its
companion CLI command `meshant semantic export`.

## What it does

Streams the authenticated user's tenant graph as RDF in the
requested serialization. Backed by the FastAPI semantic-service's
`POST /export`, which executes
`CONSTRUCT { ?s ?p ?o } WHERE { GRAPH <urn:tenant:{id}> { ?s ?p ?o } }`
on Fuseki and serializes via rdflib.

## Limits

| Knob | Value | Where it lives |
|---|---|---|
| Per-user throttle | 5 req / 5 min | `SemanticExportThrottle` in [hub/apps/semantic/views.py](../../hub/apps/semantic/views.py) |
| Hard cap | 100 million triples → HTTP 413 | [services/semantic-service/main.py](../../services/semantic-service/main.py) `_EXPORT_FORMAT_MAP` block |
| Audit | `SEMANTIC_EXPORT` action on success | view layer; payload includes byte count + format |
| Async-promotion threshold | > 100 MB triggers `JobType.SEMANTIC_EXPORT_LARGE` | (planned) — see "Async path" below |

## Supported formats

| Format | MIME type | rdflib name |
|---|---|---|
| `n-triples` (default) | `application/n-triples` | `nt` |
| `turtle` | `text/turtle` | `turtle` |
| `rdf-xml` | `application/rdf+xml` | `xml` |
| `ld+json` | `application/ld+json` | `json-ld` |

Any other value → HTTP 400 with `error.code = EXPORT_FORMAT_INVALID`.

## Common operator tasks

### Verify a customer can export

```bash
# As the customer (or impersonating their tenant — see
# admin-impersonation runbook):
meshant semantic export --format=turtle --output=/tmp/check.ttl
# Expect: a non-empty Turtle file. If 429, the customer has
# already used 5 of their 5-minute quota.
```

### Investigate "export keeps timing out" reports

1. Check `lineage_query_duration_seconds` on the Grafana semantic
   panel — sustained P99 > 5 s suggests Fuseki saturation, not
   the export itself.
2. Confirm the customer is hitting the synchronous endpoint
   (default). If their tenant graph is > 100 MB, they should be
   queued via `JobType.SEMANTIC_EXPORT_LARGE` (async path; emails
   the download link). Push them to the async path:
   ```bash
   curl -X POST https://meshant-internal.example.com/api/v1/semantic/export \
       -H "Authorization: Bearer $TOKEN" \
       -d '{"format":"turtle","async":true}'
   ```
   *(Async surface is a planned follow-up; today the synchronous
   endpoint will return 413 if the result would exceed the cap.)*

### Replay a failed export

The endpoint is idempotent (read-only on the graph). Failed
exports leave no state — just retry. The `SEMANTIC_EXPORT` audit
event is written ONLY on success, so a 429 / 503 / 413 leaves
the audit table untouched.

## Failure modes

| HTTP | error.code | What it means | Action |
|---|---|---|---|
| 400 | `EXPORT_FORMAT_INVALID` | Format string not in the allowlist | Use one of `n-triples`/`turtle`/`rdf-xml`/`ld+json` |
| 401 | (Django default) | Not authenticated | Re-issue token |
| 413 | `EXPORT_TOO_LARGE` | Tenant graph > 100M triples | Use SPARQL pagination via `/api/v1/semantic/sparql` |
| 429 | (DRF throttle) | 5 req / 5 min / user exceeded | Wait the `Retry-After` interval |
| 503 | (circuit breaker) | semantic-service unreachable | Check Fuseki + semantic-service pod health |

## Wire path

```
Browser/CLI
    │  POST /api/v1/semantic/export   {format}
    ▼
Django view  hub/apps/semantic/views.py::rdf_export
    │   - throttle (SemanticExportThrottle, 5/5min)
    │   - tenant_id derived from request.user (NEVER from body)
    │   - SemanticServiceClient().export_rdf(tenant_id, format)
    ▼
SemanticServiceClient (hub/apps/semantic/service_client.py)
    │   - read circuit breaker
    │   - POST /export to semantic-service
    ▼
FastAPI  services/semantic-service/main.py::rdf_export
    │   - validate format (Literal[...])
    │   - CONSTRUCT { ?s ?p ?o } WHERE { GRAPH <urn:tenant:{id}> { ... } }
    │   - rdflib.Graph.serialize(format=...)
    │   - 100M-triple cap → 413 EXPORT_TOO_LARGE
    ▼
Fuseki  /sparql
```

## Observability

- Backend metric: `lineage_query_duration_seconds` (existing); new
  per-export metric is a follow-up if request volume warrants.
- Audit row: `AuditEvent.action == "SEMANTIC_EXPORT"` with details
  `{format, bytes}`.
- Service-side logs: `services/semantic-service/main.py` emits a
  structured log on every export attempt.
