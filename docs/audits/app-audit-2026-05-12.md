### Async vs Sync Patterns

**Worker:** Gunicorn with UvicornWorker (ASGI). Django views are synchronous (`def`, not `async def`). 0 `async def` view functions found in `hub/apps/*/views.py`.

**Assessment:** Synchronous views on UvicornWorker are the standard Django deployment pattern. The worker handles I/O-bound requests via thread pooling. AthenaConnector async polling runs in a separate thread via `boto3`'s synchronous API (acceptable for the current scale — Athena queries are <10/min/tenant).

**Gap:** No dedicated async task queue for long-running warehouse queries. The Athena async polling pattern (ATHENA_POLL_INTERVAL_S=1.0, ATHENA_MAX_POLL_S=300) blocks a gunicorn worker for up to 5 minutes per query. Consider moving to `asyncio` + `aiohttp` for Athena or delegating to an RQ task.
